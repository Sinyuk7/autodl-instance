# AutoDL Codex 全局说明模板

将下面代码块中的内容保存到 AutoDL 主机的 `/root/.codex/AGENTS.md`。Codex 只在新会话启动时读取全局说明，修改后需要退出并重新启动 Codex。

```md
# AutoDL Host Context

这是一台用于 ComfyUI 的 AutoDL GPU 实例。处理任何任务时，以主机实测结果为准；项目文档、默认路径和缓存状态都可能过期。

## 存储规划

- `/root` 是默认 30GB 系统盘。项目源码、ComfyUI、Python 环境、Codex CLI、Mihomo 程序和个人配置放在这里，因为整个系统盘可以在实例关机后保存为个人镜像，并在其他实例恢复。
- 系统盘容量有限。模型、生成输出、下载缓存和其他大型文件不得长期放在系统盘，否则会挤占环境空间并使镜像臃肿。
- `/root/autodl-tmp` 是默认 50GB 本地数据盘。它 IO 较高，适合临时输出、下载缓存、当前工作集和少量正在使用的模型。
- 本地数据盘没有冗余、不会进入系统镜像，实例释放后会丢失。因此它不能作为完整模型库或重要数据的唯一副本。
- `/root/autodl-fs` 是同地区实例可共享的网络文件存储，具有多副本且不受实例释放影响。完整模型库、重要工作流、最终输出和长期数据应保存在这里。
- 文件存储 IO 一般。需要高 IO 的模型或数据可以临时复制到本地数据盘，任务结束后清理可重建缓存，并把重要结果保存回文件存储。
- 向 `/root/autodl-tmp` 或 `/root/autodl-fs` 大量写入前，必须用 `findmnt -T`、`mountpoint`、`df -hT` 和 `df -i` 确认真实挂载、剩余空间和 inode。目录存在不代表对应存储已经正确挂载。

## 镜像与迁移

- AutoDL 保存镜像只保存整个系统盘，不包含本地数据盘或文件存储。保存镜像需要用户先关机，再在 AutoDL 控制台执行；Codex 不应自行尝试模拟该操作。
- 加载或更换镜像会清空当前系统盘，但不会影响本地数据盘。
- 同地区克隆实例以系统盘为模板创建新实例，并可由用户选择是否复制本地数据盘。文件存储由同地区实例单独挂载，不需要放进镜像。
- 默认把保存的镜像视为用户自己的私人环境，不对外分享。若用户明确要求共享，必须先提醒并清理代理订阅、Token、SSH 私钥、Codex 登录信息和其他机器秘密。

## 项目与环境

- 本项目工作副本预期位于 `/root/autodl-instance`，ComfyUI 预期位于 `/root/ComfyUI`。操作前仍需验证真实路径，不能仅依据预期路径创建或覆盖文件。
- 代码以 Git 仓库为来源，重要的非代码数据以文件存储为长期来源。本地数据盘中的内容默认视为工作副本或缓存。
- ComfyUI 应使用独立 Python 环境。不要因为依赖问题直接修改 AutoDL 的基础 Conda/Jupyter 环境，因为这会污染平台环境并增加镜像中的隐式状态。
- 不要安装或替换 NVIDIA 驱动来解决普通 Python/CUDA 包问题。先检查 `nvidia-smi`、实际 Python、Torch 和 CUDA 兼容性，再提出最小修改。

## 秘密与权限

- 代理订阅、节点、API Token、SSH 私钥、Codex 登录信息和本地 secrets 可以保留在系统盘，随私人镜像恢复，但必须使用受限权限，敏感文件通常应为 `600`。
- 不得把秘密提交到 Git，也不得为了避开镜像而把明文秘密移动到本地数据盘或文件存储。
- 检查敏感文件时，只报告路径、是否存在、所有者、权限、大小和修改时间；除非用户明确要求，否则不得读取、打印或总结其内容。

## 操作安全

- 对不熟悉的环境，先执行只读检查并报告事实，再进行安装、迁移、覆盖、删除或服务重启。
- 保留现有 Git 修改、未跟踪文件和用户数据。不得擅自 reset、revert、清空目录、重置实例或更换镜像。
- 停止进程前，必须通过 PID、命令行、可执行文件和工作目录确认归属。不得为了释放端口而杀死所有占用该端口的进程。
- 停止已确认归属的进程时，优先使用 `SIGTERM` 并等待正常退出；只有正常退出失败且用户允许时才考虑强制终止。
- 大范围扫描会消耗 IO。优先检查明确目录并限制深度，除非确实需要，否则不要递归扫描整个 `/root`、数据盘或文件存储。
- 未经用户明确要求，不要 commit、push、分享镜像或执行 AutoDL 控制台层面的操作。

## 网络与代理

- Mihomo 服务和 shell 代理变量是两件事。启动 Mihomo 不要求执行 `eval "$(autodl turbo)"`，也不要默认修改 shell 启动文件或设置全局系统代理。
- 需要代理的命令优先使用单命令或单进程的 `HTTP_PROXY`、`HTTPS_PROXY`，并为本地检查保留 `NO_PROXY=127.0.0.1,localhost`。
- 测试本地 ComfyUI 时必须显式绕过代理。测试外网时使用短超时，并说明测试走的是直连、AutoDL 学术加速还是 Mihomo。
- 不得把代理监听地址暴露到非回环接口，除非用户明确要求并理解风险。

## ComfyUI 与端口

- AutoDL 为实例提供 6006/6008 的公网映射。公网访问失败时，依次检查服务进程、实际监听端口、监听地址、本地 HTTP 响应和 AutoDL 映射协议。
- 本地检查使用明确绕过代理的 `127.0.0.1` 请求。需要公网映射时，ComfyUI 通常应监听 `0.0.0.0`，但修改启动参数前先确认当前进程和配置。
- 本地服务正常而公网返回 AutoDL 通用 404 时，应将其记录为平台映射或协议问题，不能直接判定为 ComfyUI 安装失败。

## 输出要求

- 明确区分已验证事实、合理推测和未验证项目。
- 问题应区分为主机环境、AutoDL 平台、项目代码或用户配置，并给出证据和最小修复建议。
- “没有发现”不等于“已经正常”；无法验证时必须明确标记。
```
